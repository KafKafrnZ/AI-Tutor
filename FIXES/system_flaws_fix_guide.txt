[FIX-1] Cookie name mismatch — auth middleware never works
FILE: frontend/middleware.ts, Line 9
---------------------------------------------------------------------------
PROBLEM:
  The middleware reads: request.cookies.get('access token')
  The backend sets:     key="access_token"
  Space vs underscore — they never match. Every protected route lets anyone in.

FIX:
  Change line 9 from:
    const token = request.cookies.get('access token')?.value
  To:
    const token = request.cookies.get('access_token')?.value

[FIX-4] RAG is completely disconnected — FAISS / PYQ context never reaches the AI
FILES: backend/modules/rag.py, backend/modules/tutor.py, backend/app/main.py
---------------------------------------------------------------------------
PROBLEM:
  rag.py has a full FAISS search pipeline (load_pyqs → initialize_rag → search_pyqs)
  but tutor.py's ask_tutor() never calls it.
  The /ask endpoint passes data.context which the frontend never populates with RAG results.
  Students get answers with zero previous-year-question context.

FIX (3 steps):
  Step 1 — In tutor.py, import and call RAG at the top of ask_tutor():
    from modules.rag import load_pyqs, initialize_rag, search_pyqs

    async def ask_tutor(question: str, context: str = "") -> str:
        # Load RAG context if no context was provided
        if not context:
            pyqs = load_pyqs()
            index, pyqs = initialize_rag(pyqs)
            results = search_pyqs(question, pyqs, index, top_k=3)
            context = "\n".join([r["data"].get("question", "") for r in results])
        ...rest of function unchanged...

  Step 2 — Do the same inside ask_tutor_stream() in tutor.py (same pattern).

  Step 3 — In agent.py compiler_agent, inject the RAG context into the prompt
    before generating the final answer. Pass question to search_pyqs first.

  Note: INDEX_CACHE and PYQS_CACHE in rag.py ensure the index is only built once.
        Subsequent calls are fast (cache hit).

[FIX-5] LangGraph routing is a fake passthrough — supervisor decision is ignored
FILE: backend/app/agent.py, Lines 49-58
---------------------------------------------------------------------------
PROBLEM:
  The supervisor generates a routing decision ("route to Math model") but
  there are no conditional edges in the graph. It always goes:
    supervisor → expert → compiler
  The decision text is generated but immediately thrown away.

FIX:
  Option A (Quick): Remove the supervisor node entirely since it adds latency
    with zero benefit. Go directly: expert → compiler.

  Option B (Proper): Add conditional routing using LangGraph's add_conditional_edges.
    Update AgentState to include a "route" field.
    Have supervisor_agent return {"route": "math"} or {"route": "language"} etc.
    Create separate expert nodes (math_expert, reasoning_expert, language_expert).
    Use add_conditional_edges("supervisor", lambda s: s["route"], {...}) to branch.

  Recommended: Do Option A now, Option B in Phase 1 of the roadmap.


[FIX-6] Streaming uses 8B model with generic prompt; non-streaming uses 70B with full prompt
FILES: backend/app/agent.py, backend/modules/tutor.py, backend/app/main.py

  /ask        → tutor.py → Groq llama-3.3-70b-versatile + full IBPS SO system prompt

    @app.post("/ask/stream")

        async def event_generator():
            async for token in ask_tutor_stream(request.question, request.context):
                yield {"data": token}
        return EventSourceResponse(event_generator())

  Import ask_tutor_stream from modules.tutor at the top of main.py.
  Wire RAG into ask_tutor_stream() as described in FIX-4.


[FIX-7] No logout endpoint — users cannot log out
FILE: backend/app/main.py
---------------------------------------------------------------------------
PROBLEM:
  The /login endpoint sets an httpOnly cookie.
  There is no /logout endpoint to clear it.
  Users are stuck until the 1-hour cookie expires.

FIX:
  Add this endpoint to main.py:

    @app.post("/logout")
    def logout(current_user = Depends(get_current_user)):
        response = JSONResponse(content={"message": "Logged out"})
        response.delete_cookie(
            key="access_token",
            httponly=True,
            secure=True,
            samesite="lax"
        )
        return response

  Then in the frontend AppLayout.tsx, call POST /logout when the user
  clicks the logout button, then redirect to /login.


[FIX-12] No Alembic migrations — schema changes destroy data
FILE: backend/ (missing alembic setup)
---------------------------------------------------------------------------
PROBLEM:
  init_db() runs Base.metadata.create_all() which only creates tables if they
  don't exist. Adding a new column to an existing deployed table does nothing.
  Changing the schema requires dropping the table or writing raw ALTER TABLE SQL.
  There is no migration history or rollback.

FIX (setup steps):
  1. Install: pip install alembic
  2. In backend/: run  alembic init alembic
  3. In alembic/env.py: set target_metadata = Base.metadata
     and configure the DATABASE_URL from your settings.
  4. Generate first migration: alembic revision --autogenerate -m "initial_schema"
  5. Apply: alembic upgrade head
  6. From now on, any model change → alembic revision --autogenerate → alembic upgrade head
  7. Remove the init_db() call from the lifespan manager (alembic handles this now).

  This is mandatory before any roadmap Phase 1 DB schema changes.

[FIX-8] No email format validation on signup
FILE: backend/app/main.py, Line 121-127
---------------------------------------------------------------------------
PROBLEM:
  The signup endpoint accepts any string as an email (e.g. "notanemail").

  Change:
    from pydantic import BaseModel
    class SignupRequest(BaseModel):
        email: str
  To:

[FIX-9] No refresh token — users silently logged out after 1 hour
FILE: backend/app/core/auth.py, backend/app/main.py
---------------------------------------------------------------------------
PROBLEM:
  Access token expires after 1 hour (ACCESS_TOKEN_EXPIRE_MINUTES).
  There is no refresh token mechanism.
  Mid-session expiry causes silent failures — API calls return 401 but the
  UI doesn't redirect to login, it just shows broken/empty states.

FIX (minimal approach):
  Option A (simple): Extend token expiry to 7 days for now.
    In config.py: ACCESS_TOKEN_EXPIRE_MINUTES = 60 * 24 * 7

  Option B (proper): Implement a refresh token.
    On login, issue a second long-lived refresh token (30 days) in a separate cookie.
    Add a POST /refresh endpoint that reads the refresh cookie and issues a new access token.
    Frontend should intercept 401 responses and call /refresh before retrying.

  Recommended: Do Option A immediately, plan Option B for Phase 2.

[FIX-11] MasterQuestion.test_id has no foreign key constraint
FILE: backend/app/models/database.py, Line 47
---------------------------------------------------------------------------
PROBLEM:
  test_id = Column(Integer, index=True)
  There is no ForeignKey("mock_tests.id") on this column.
  Questions can reference test IDs that don't exist.
  Deleting a mock test leaves orphaned questions in the table.

  And on MasterQuestion:
    test = relationship("MockTest", back_populates="questions")

  Do this as an Alembic migration.


[FIX-14] New httpx.AsyncClient created on every API call — no connection reuse
FILE: backend/modules/tutor.py
---------------------------------------------------------------------------
PROBLEM:
  Every call to run_cloud_model() and run_cloud_model_stream() opens a brand new
  httpx.AsyncClient() and closes it after. Under load, this creates connection
  churn and DNS overhead for every single request.

FIX:
  Create a shared client at module level and reuse it:

    # At top of tutor.py, after imports:
    _http_client: httpx.AsyncClient | None = None

    def get_http_client() -> httpx.AsyncClient:
        global _http_client
        if _http_client is None or _http_client.is_closed:
            _http_client = httpx.AsyncClient(timeout=75.0)
        return _http_client

  Then in run_cloud_model() and run_cloud_model_stream():
    Replace: async with httpx.AsyncClient() as client:
    With:    client = get_http_client()
             (remove the async with wrapper, just use client directly)

  Optionally: register client.aclose() in the FastAPI lifespan shutdown.


[FIX-15] /stats endpoint has no caching — runs full DB+pandas on every request
FILE: backend/app/main.py, Line 253
---------------------------------------------------------------------------
PROBLEM:
  Every call to GET /stats triggers load_data() (DB query) + calculate_accuracy()
  + get_overall_stats() + get_weak_areas() — all pandas operations.
  If a user refreshes the dashboard 10 times in a minute, that's 10 full cycles.

FIX (simple):
  Add a short in-memory cache using functools.lru_cache or a dict with timestamps.

  Quick approach — cache per user for 60 seconds:
    import time
    _stats_cache: dict = {}  # {user_id: (timestamp, result)}

    @app.get("/stats")
    def stats(db=Depends(get_db), current_user=Depends(get_current_user)):
        now = time.time()
        cached = _stats_cache.get(current_user.id)
        if cached and (now - cached[0]) < 60:
            return cached[1]
        # ... existing stats logic ...
        result = { ...stats dict... }
        _stats_cache[current_user.id] = (now, result)
        return result

  Proper approach for Phase 2: Use Redis cache on Railway.


[FIX-17] Zustand store has no auth/user state — every page re-fetches /me
FILE: frontend/store/useAppStore.ts
---------------------------------------------------------------------------
PROBLEM:
  The store tracks tutor messages and practice state but not the logged-in user.
  Every page/component that needs the user's name, email, or plan calls GET /me
  independently, causing redundant API calls on every navigation.

FIX:
  Add user state to the Zustand store:

    interface User {
      id: number;
      name: string;
      email: string;
      plan: string;
    }

    interface AppState {

    setUser: (user) => set({ user }),

  Then in AppLayout.tsx: fetch /me once on mount, call setUser(), and all
  child components read from the store instead of fetching again.


[FIX-19] No React error boundaries — one crash = blank white screen
FILE: frontend (all page components)
---------------------------------------------------------------------------
PROBLEM:
  No ErrorBoundary components exist. If any component throws during render
  (e.g. API returns unexpected data, undefined.map() etc.), the entire page
  goes blank with no user-facing message.

FIX:
  Create frontend/components/ErrorBoundary.tsx:

    "use client";
    import { Component, ReactNode } from "react";

    export default class ErrorBoundary extends Component<
      { children: ReactNode },
      { hasError: boolean }
    > {
      state = { hasError: false };
      static getDerivedStateFromError() { return { hasError: true }; }
      render() {
        if (this.state.hasError)
          return <div className="p-8 text-center text-red-400">
            Something went wrong. Please refresh the page.
          </div>;
        return this.props.children;
      }
    }

  Wrap each page's main content with <ErrorBoundary>...</ErrorBoundary>.

[FIX-18] Zustand store has no persistence — page refresh clears all state
FILE: frontend/store/useAppStore.ts
---------------------------------------------------------------------------
PROBLEM:
  Tutor conversation history and practice state is stored only in memory.
  Refreshing the page wipes everything. Users lose their conversation mid-session.

FIX:
  Use the zustand persist middleware:

    import { create } from 'zustand';
    import { persist } from 'zustand/middleware';

    export const useAppStore = create<AppState>()(
      persist(
        (set) => ({
          // ... all existing state and setters ...
        }),
        {
          name: 'ibps-so-app-store',  // localStorage key
          partialize: (state) => ({   // only persist these fields
            tutorMessages: state.tutorMessages,
          }),
        }
      )
    );

  Note: Do not persist practiceAnswers — stale answers from a previous session
  would pre-fill a new session's quiz, which is confusing.
