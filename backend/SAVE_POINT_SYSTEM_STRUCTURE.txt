Backend Overview
Path: backend/

Framework and main libraries:
- FastAPI
- Uvicorn
- SQLAlchemy ORM
- PostgreSQL through psycopg2
- Pydantic
- python-jose JWT authentication
- bcrypt password hashing
- SlowAPI rate limiting
- sse-starlette for server-sent events
- Groq API for cloud LLM inference
- LangGraph + LangChain Groq for streaming/multi-agent tutor flow

- Pandas/Numpy for stats and analysis

Database Structure
Database engine:
- PostgreSQL
- SQLAlchemy ORM

Tables/models:
- users
  Stores account identity, hashed password, plan, and creation time.

- mock_tests
  Stores a user's mock test attempts, section, attempted count, correct count,
  and time taken.

- master_questions
  Stores mock-test questions by test id, section, topic, options, answer, and explanation.

- error_logs
  Stores user mistakes:
  question text, user answer, correct answer, explanation, and date added.

Current AI Flow
Normal tutor endpoint:
1. Frontend sends a question to backend /ask.
2. Backend verifies JWT user.
3. backend/app/main.py calls modules/tutor.py::ask_tutor.
4. ask_tutor builds the IBPS SO tutor prompt.
5. Groq llama-3.3-70b-versatile is called.
6. If cloud fails or returns too little content, Ollama phi3 is attempted as fallback.
7. Backend returns the final answer to the frontend.

Streaming tutor endpoint:
1. Frontend calls /ask/stream.
2. backend/app/main.py starts EventSourceResponse.
3. app/agent.py LangGraph runs supervisor, expert, and compiler nodes.
4. Thought events and final result events are streamed back.

Practice flow:
1. Frontend practice page sends topic to POST /practice.
2. Backend calls generate_questions.
3. Groq returns a JSON array of 30 MCQs.
4. Backend cleans/parses JSON and returns questions to frontend.

Mock test flow:
1. Frontend requests GET /mock-tests/{test_id}/questions.
2. Backend loads MasterQuestion rows from PostgreSQL.
3. Frontend displays questions.
4. Results can be saved through POST /save-mock-test.

Error log flow:
1. Frontend sends wrong answers to POST /save-errors.
2. Backend saves ErrorLog rows for the current user.
3. Frontend can retrieve them through GET /error-log.

Progress/stats flow:
1. Frontend calls GET /stats.
2. Backend loads user mock-test data through modules/data_analyzer.py.
3. Backend returns average accuracy, total tests, recent tests, and weak areas.

Revision plan flow:
1. Frontend/backend calls GET /revision-plan.
2. Backend asks data_analyzer for an AI-generated study/revision plan based on recent mistakes.

Current Integration Notes
- Frontend and backend are separate apps.
- Frontend dev server is expected around localhost:3000.
- Backend CORS allows localhost:3000 and 127.0.0.1:3000 by default.
- Backend DATABASE_URL defaults to local PostgreSQL if not overridden by .env.
- GROQ_API_KEY is required for cloud AI features.
- RAG/FAISS code is present, but should be explicitly integrated into /ask if we want
  automatic PYQ retrieval for every tutor question.
